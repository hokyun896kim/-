# 📈 미국주식 분석·매매 시스템

개인투자자가 **미국주식을 체계적으로 분석하고 연습 매매**할 수 있도록 만든
올인원 시스템입니다. 기술적 분석 + 기본적 분석을 종합 점수로 환산해 매수/매도
의견을 제시하고, 웹 대시보드와 모의매매(페이퍼 트레이딩) 기능을 제공합니다.

> ⚠️ **면책**: 본 시스템은 교육·연구 목적입니다. 제공되는 점수와 추천은 투자
> 자문이 아니며, 모든 투자 판단과 결과의 책임은 사용자 본인에게 있습니다.

> 🔬 **검증 결과 — 이 점수는 매매 신호가 아닙니다**
>
> 80종목 전 기간 이벤트 스터디로 측정한 결과, 종합점수는 **미래 수익률을
> 예측하지 못했습니다** (IC −0.016, 다중검정 보정 후 유의성 없음).
> 그래서 등급 라벨을 '적극 매수/매수/보유/매도'에서 **상위/중상/중립/중하/하위**
> 로 바꿨습니다 — 매매 지시가 아니라 점수 구간에서의 위치입니다.
>
> 또 기술 점수의 **추세추종 성분은 예측 방향이 반대**로 나와(단조성 −1.00,
> t=−3.04, 편향제거 후 연 −6.89%) 기본 가중치를 **0** 으로 뺐습니다
> (`technical.trend_weight`). → [자세히](#-점수-검증)

## ✨ 주요 기능

| 영역 | 내용 |
|------|------|
| **🤖 AI 비서** | 자연어로 물어보면 아래 분석 모듈을 대신 실행해 답합니다. `ANTHROPIC_API_KEY` 가 있으면 Claude 로 자유 대화, 없으면 키워드 기반 규칙 엔진으로 동작 (오프라인 가능) |
| **선취매 레이더** | 조용한 매집(OBV↑·횡보)+상승여력+변곡 시작 종목을 발굴, 과열·급등은 감점 (남보다 먼저, 느긋하게) |
| **시장 분석** | 나스닥·S&P500·다우 + VIX 공포지수, 50/200일선·골든/데드크로스, **수급(OBV)**·변동성·주요 레벨, **향후 방향성 자동 해설**, 해외 아티클 |
| **헤게모니 스프레드** | 영업이익YoY−매출YoY로 이익 레버리지 발굴, 연간 vs 분기TTM 가속/피크아웃, 랭킹 (yfinance 손익계산서 라이브 계산) |
| **시가총액 스크리너** | 미국 대형주 유니버스에서 **시총 상위 N%** · 섹터로 필터링해 종합점수 랭킹 (실시간 시총 갱신·일일 캐시) |
| **기술적 분석** | 이동평균(SMA/EMA), RSI, MACD, 볼린저밴드 → 매수/중립/매도 신호 |
| **기본적 분석** | PER, PBR, ROE, 순이익률, 매출·이익 성장률, 부채비율, 배당 채점 |

| **최근 실적** | 분기 EPS 예상 vs 실제, **서프라이즈(%)**, 매출 |
| **이벤트** | 다음 **실적 발표일(D-day)**, 배당락일·배당금 |
| **해외 뉴스 분위기** | 헤드라인 수집 + 감성분석 → 긍정/중립/부정 종합 분위기 점수 |
| **웹 대시보드** | 다크 트레이딩 터미널 테마 · 시장 · 선취매 · 스크리너 · 종목 상세 · 헤게모니 · 비교 · 백테스트 · 시뮬레이터 · 모의매매 · 닥터 · **검증** · 가이드 12개 화면 (선택한 화면만 렌더링해 첫 로드가 가볍습니다) |
| **모의매매** | 가상 자본으로 매수/매도 연습, 수익률·실현손익 추적(자동 저장) |
| **공포·탐욕 지수** | VIX·모멘텀·RSI·신고가 근접도를 합친 0~100 시장심리 게이지 (CNN 스타일) |
| **종목 비교 레이더** | 가치·성장·수익성·모멘텀·안정성 5팩터를 레이더로 다종목 비교 |
| **시뮬레이터** | 과거 투자 수익 계산(타임머신) + 몬테카를로 미래 주가 확률 분포·목표 도달확률 |
| **포트폴리오 닥터** | 보유종목 분산·집중도·변동성·베타 진단 + 섹터 도넛 + 리밸런싱 제안 |
| **백테스팅** | 매매 전략(골든크로스·RSI·MACD·종합점수)을 과거에 적용해 수익률·MDD·샤프·승률을 단순보유와 비교 |
| **점수 검증** | 점수 → 미래 초과수익률 이벤트 스터디. IC·t값·구간별 수익률로 **예측력이 실제로 있는지** 측정 (추세 vs 역추세 분리 비교) |
| **CLI** | 터미널에서 빠르게 종목 분석 |
| **오프라인 모드** | 네트워크 없이도 샘플 데이터로 전체 기능 시연/테스트 |

## 🚀 빠른 시작

```bash
# 1) 의존성 설치
pip install -r requirements.txt

# 2) 웹 대시보드 실행 (권장)
streamlit run stocksystem/app/dashboard.py
# 브라우저에서 http://localhost:8501 접속

# 3) 또는 터미널 CLI
python cli.py analyze AAPL MSFT NVDA   # 특정 종목
python cli.py watchlist                # config.yaml 관심종목 전체

# 4) AI 비서에게 말로 물어보기
python assistant_cli.py "엔비디아 어때?"
python assistant_cli.py                # 대화 모드
```

### 오프라인/데모로 먼저 둘러보기
실시간 데이터(Yahoo Finance) 접속이 어려운 환경에서는 샘플 데이터로 동작을
확인할 수 있습니다.

```bash
python cli.py analyze AAPL MSFT --provider sample
```
대시보드에서는 사이드바의 **데이터 소스**를 `sample` 로 바꾸면 됩니다.

## 🤖 AI 비서

"엔비디아 어때?" 처럼 **말로 물어보면** 이 시스템의 분석 모듈을 대신 실행해
답해주는 대화형 인터페이스입니다. 대시보드 첫 화면(`🤖 비서`)과 터미널
(`assistant_cli.py`) 양쪽에서 같은 엔진을 씁니다.

```bash
python assistant_cli.py "기술주 중에 점수 높은 거 5개 골라줘"
python assistant_cli.py --provider sample     # 오프라인 데모 데이터로
python assistant_cli.py --engine rules        # LLM 없이 규칙 엔진만
```

### 두 개의 엔진 (하이브리드)

| | Claude 엔진 | 규칙 엔진 |
|---|---|---|
| **조건** | `ANTHROPIC_API_KEY` 또는 `ant auth login` 프로필이 있을 때 | 자격증명이 없을 때 (기본) |
| **이해 범위** | 자유로운 대화. 여러 도구를 엮고, 애매하면 되묻습니다 | 키워드/패턴 매칭으로 도구 하나를 고릅니다 |
| **비용·네트워크** | API 호출 비용 발생 | 없음 — 완전 로컬 |
| **되는 것** | "엔비디아랑 AMD 비교하고, 이긴 쪽 뉴스 분위기도 봐줘" | "엔비디아 어때?", "선취매 종목 찾아줘" 등 자주 쓰는 십수 가지 |

`config.yaml` 의 `assistant.engine` 이 `auto` 면 자격증명 유무로 자동
선택합니다. Claude 호출이 실패해도(키 만료·네트워크 단절) 규칙 엔진으로
내려가 대화가 끊기지 않습니다.

```bash
pip install anthropic
export ANTHROPIC_API_KEY=sk-ant-...
python assistant_cli.py          # 이제 자유 대화 모드
```

### 설계 원칙 — 비서는 숫자를 지어내지 않습니다

1. **모든 수치는 도구가 만듭니다.** 비서(LLM 포함)는 주가·점수·비율을 직접
   생성하지 않습니다. 시스템 프롬프트가 이를 금지하고, 도구가 값을 주지 않으면
   "데이터가 없습니다"라고 답하게 돼 있습니다. → 대시보드·CLI·비서가 **항상
   같은 숫자**를 냅니다 (`tests/test_assistant.py::test_analyze_stock_matches_scoring_module`).
2. **매매 지시를 하지 않습니다.** 종합점수는 [검증](#-점수-검증)에서 예측력이
   확인되지 않았습니다(IC −0.016). 비서는 "사세요/오를 겁니다" 대신 지금 지표가
   어떤 상태인지를 서술하고, 답변마다 그 한계를 덧붙입니다.
3. **모의매매는 확인 후에만.** `paper_trade` 는 종목과 수량이 분명할 때만
   실행하고, 체결가와 잔여 현금을 그대로 보고합니다. 실제 주문이 아닙니다.
4. **스캔 범위는 유한합니다.** 스크리너·선취매는 시총 상위 40종목까지만 훑고
   (대화형 응답성 때문), 잘린 사실을 답변에 표시합니다.

> ⚠️ 비서의 답변은 투자자문이 아닙니다. 모든 판단과 책임은 본인에게 있습니다.

### 첫 로드 성능

대시보드는 `st.tabs` 대신 `st.segmented_control` 로 화면을 전환합니다.
`st.tabs` 는 **보고 있지 않은 탭의 본문까지 매 rerun 마다 전부 실행**하기
때문에, 12개 화면이 모두 돌면 캐시가 빈 첫 방문에 Yahoo 조회가 **약 71회**
나갑니다 (특히 `.info` 는 건당 1~3초). Streamlit Community Cloud 는 공용 IP 라
그 정도 연속 호출에서 429 로 막히기 쉽습니다.

선택한 화면만 렌더링하도록 바꿔 **첫 로드 조회가 71회 → 5회(93% 감소)** 로
줄었습니다. 화면 전환 때 rerun 이 일어나지만 데이터는 `@st.cache_data` 에
남아 두 번째부터는 즉시 그려집니다.

## ⚙️ 설정 (`config.yaml`)

```yaml
watchlist: [AAPL, MSFT, NVDA, ...]   # 관심종목
data_provider: yahoo                 # yahoo(실시간) | sample(오프라인)
technical:                           # 지표 파라미터
  sma_short: 20
  rsi_period: 14
  ...
fundamental:                         # 펀더멘털 채점 방식
  sector_neutral: false              #   true = PER/PBR/부채비율을 섹터 내 백분위로
  min_peers: 4                       #   섹터당 최소 표본 (미만이면 절대 구간)
weights:                             # 종합점수 가중치 (합 1.0)
  technical: 0.5
  fundamental: 0.5
recommendation:                      # 추천 구간 (0~100)
  strong_buy: 75
  buy: 60
  ...
paper_trading:
  initial_cash: 100000               # 모의계좌 초기자본 (USD)
assistant:                           # AI 비서
  engine: auto                       #   auto | claude | rules
  model: claude-opus-5
  max_turns: 6                       #   한 질문에 허용할 도구 호출 라운드
  effort: medium                     #   low | medium | high | xhigh | max
```

## 🔬 점수 검증

이 시스템의 점수는 전부 **'그럴듯한 규칙'** 으로 만들어졌을 뿐, 실제로 미래
수익률을 예측하는지 측정된 적이 없었습니다. `stocksystem/research/` 가 그
공백을 메웁니다.

```bash
# 시총 상위 80종목, 최근 5년. 추세 vs 역추세 중 무엇이 수익을 냈는지 비교
python research_cli.py --top 80 --period 5y --compare --out data/validation.json
```

측정 방식은 **이벤트 스터디**입니다. t 시점 점수 → t~t+20/60일의 **SPY 대비
초과수익률**을 짝지어 점수 구간별 평균 수익률과 **IC(순위상관)** 을 냅니다.

| 지표 | 읽는 법 |
|---|---|
| **IC** | 점수 순위와 이후 수익률 순위의 상관. 0이면 무작위와 다를 바 없음 |
| **t값** | \|t\| ≥ 2 면 유의 — 단, 가설을 여러 개 검정하면 **Bonferroni 보정** 임계값(가설 6개면 2.64)을 넘어야 함 |
| **롱숏(보정)** | 최상위 − 최하위 구간, **날짜별 유니버스 평균을 뺀** 값 |
| **연환산순** | 왕복 거래비용 차감 후 연 수익률 (`--cost`, 기본 5bp) |
| **단조성** | 점수가 오를수록 수익률도 오르는가 (1.0 = 완벽) |

**유니버스 편향 제거가 왜 필요한가**: `universe.csv` 는 **현재** 시총 상위
종목입니다. 그렇게 커진 기업만 모아둔 집합이라 SPY 를 이기는 게 당연합니다
(실측 연 +7.7%). 그 상태로는 최하위 점수 구간까지 초과수익이 플러스로 나와
"점수가 높으면 수익이 난다"와 "이 종목들이 원래 잘 나간다"를 구분할 수
없습니다. 날짜별 횡단면 평균을 빼면 남는 것이 점수의 순수 기여분입니다.

구간이 채워지는 시점도 보정됩니다 — 추세 점수는 상승장에 최상위 구간이,
하락장에 최하위 구간이 몰리기 때문에 원시 스프레드는 '신호의 힘'과 '그 구간이
채워진 시점의 시장 상황'을 섞어버립니다.

**편향 방지**: 점수는 t 시점까지의 데이터만 쓰고 수익률은 t 이후만 봅니다
(룩어헤드 없음). 일별 중복표본으로 t값이 부풀지 않도록 **구간이 겹치지 않게
h일 간격으로 샘플링**합니다. **유니버스 편향**은 날짜별 횡단면 평균을 빼서,
**다중검정**은 Bonferroni 임계값을 함께 표시해서, **거래비용**은 연환산 순수익과
손익분기 비용을 계산해서 다룹니다. 생존편향(상장폐지 종목 부재)과 공매도
차입비용은 여전히 미반영이며 리포트에 경고로 명시됩니다.

**하네스 자체도 검증합니다.** 랜덤워크에서는 "예측력 없음"을, 추세가 실제로
이어지도록 만든 인공 시장에서는 "예측력 있음"을 반드시 답해야 한다는 테스트가
있습니다 (`tests/test_eventstudy.py`). 후자가 없으면 항상 "예측력 없음"만
뱉는 고장난 저울일 수 있습니다.

> 로컬에서 Yahoo 접속이 막히면 GitHub **Actions → Validate Score
> Predictiveness → Run workflow** 로 돌릴 수 있습니다 (매주 토요일 자동 실행).

### 알려진 한계

- **펀더멘털 절반은 검증 불가**입니다. yfinance `.info` 는 *현재 시점의*
  PER/ROE 만 주기 때문에 과거 특정일의 재무를 복원할 수 없습니다
  (point-in-time 데이터 부재). 따라서 검증 대상은 **기술 점수 계열뿐**입니다.
- 기술 점수는 **추세추종 3개 + 역추세 2개** 를 산술평균합니다. 철학이 정반대라
  강한 상승주는 "과열"로 감점되고 급락주는 "과매도"로 가점됩니다. 이제
  `trend_score` / `reversion_score` 로 분리해 각각 측정할 수 있습니다.
- 기술 점수는 신호가 이진이라 **단계가 12개뿐**입니다(추세만 보면 4개).
  순위 도구로서 해상도가 낮아 IC 가 구조적으로 눌립니다.
- 펀더멘털 PER/PBR 구간이 **섹터 무관 절대 기준**이라 은행·통신이 구조적으로
  고득점합니다. `config.yaml` 의 `fundamental.sector_neutral: true` 로 섹터
  백분위 채점으로 바꿀 수 있습니다 (기본은 기존 동작 유지 — 어느 쪽이 나은지도
  아직 검증 전이라 조용히 바꾸지 않았습니다).

## 🧠 점수 산정 방식 (중급자 참고)

**기술 점수**: 5개 신호(SMA 교차, 가격 위치, RSI, MACD, 볼린저밴드)를 각각
매수(1)/중립(0.5)/매도(0)로 평가해 평균 → 0~100.

**펀더멘털 점수**: 각 재무 지표를 구간별로 채점한 뒤 가중평균.
- 밸류에이션(PER/PBR): **낮을수록** 가점
- 수익성(ROE/순이익률), 성장성(매출/이익): **높을수록** 가점
- 재무건전성(부채비율): **낮을수록** 가점
- 데이터가 없는 지표는 자동 제외 후 가중치 재정규화

**구간 등급**: 종합점수 → 상위(≥75) / 중상(≥60) / 중립(≥40) / 중하(≥25) /
하위. **매매 추천이 아니라 점수 구간에서의 위치입니다** — 검증에서 이 점수는
미래 수익률을 예측하지 못했습니다.

**기술 점수의 기본값 변경**: `trend_weight: 0.0` 이므로 기본 설정에서 기술
점수는 **역추세(RSI·볼린저) 성분만** 씁니다. 추세추종 성분은 검증에서 예측
방향이 반대로 나와 제외했습니다. 그 결과 **꾸준히 오르는 종목은 점수가 낮게
나옵니다** — 직관에 반하지만 측정 결과에 맞는 동작입니다. 옛 동작으로
되돌리려면 `trend_weight: 0.5` 로 설정하세요.
