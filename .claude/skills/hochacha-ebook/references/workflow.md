# 작업 흐름

출처: superpowers(MIT) brainstorming·writing-plans·subagent-driven-development·verification-before-completion, caveman(MIT) investigate-first·verify-and-stop, ponytail 리뷰 양식. 원칙만 옮겼고 훅·설치기는 쓰지 않는다.

## 1. 기획 (승인 게이트)
- 묻기는 한 번에 하나, 답이 결과물을 바꿀 때만. 정하지 않은 기본값은 말로 밝힌다
- 독자 / 왜 지금 / 성공 기준 / 하지 않을 것(예: 상품 추천서가 되면 실패) / 시리즈 다른 책과의 차이
- 구성안 2~3개를 장단점과 함께 → 저자 승인 → `ebook/plans/bookN_기획안.md`
- **기획안 승인 전 본문 집필 금지**

## 2. 장별 집필 계획
장마다: 원고 구간 · 앞 장에서 정의한 용어·숫자(이어받을 것) · 도입 장면 · 표·그림 · 검증 방법(출처, 윤문 게이트).
자기검토 5항: 기획안 누락 없음 / "적절히 보강" 같은 결정 없는 문장 없음 / 용어·숫자가 장 사이에 일관 / 사실 확인 초점 목록 / 분량 비례

## 3. 병렬 에이전트 분배
- 장이 서로 독립일 때만 병렬. **같은 파일을 여러 에이전트가 동시에 편집 금지** → 각자 `chN_new.md` 같은 별도 파일에 쓰고 사람이 검증 후 이어 붙인다
- 프롬프트에는 지침 파일 경로와 해당 장 파일 경로만(원고 전체 붙여넣기 금지)
- 이어 붙이기 전 자동 검증: 표·`>`·`###`·목록 줄 순서 동일, 숫자 신규 없음, 인용 보존(도입·마무리 구간 예외)
- 동시 20개 이하. 사용량 한도에 걸리면 완료된 파일부터 반영하고 나머지는 재개

## 4. 진행 장부
`ebook/plans/progress.md`에 장별 상태와 결정을 남긴다: `결정: 무엇 — 왜 — 틀리면 비용`. 컨텍스트가 압축돼도 다시 하지 않게.

## 5. 끝내기 전 검증
- 주장 전에 증거: "빌드 성공"은 종료 코드, "통과"는 check_publish.py 출력, "그림 정상"은 PNG를 직접 본 것
- 거절·오류 원인 분석은 추측보다 조사 먼저(회신 원문·검수 문서·파일 내용 대조)
- 검수 보고 양식: 번호 / 무엇 / 문제 / 수정안 / 안 고치면 생기는 일
- 원고에 보류할 것은 `보류:` 표시로 남기고 progress.md에 모은다
